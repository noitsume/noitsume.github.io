IMPLEMENTED
1. Bake workflow
   - Settings Studio now exposes a real Mulai Bake gate after a final ExperienceDNA is selected.
   - /rooms/{roomId}/bake accepts configuring/baking state and renders Bake progress.
   - Client invokes authenticated + CSRF-protected synchronous Bake API.
   - Progress UI: Preflight -> Build Manifest -> Publish Token.
   - Failure returns Room to configuring; retry remains available.
   - Success routes to /rooms/{roomId}/finish.

2. Deterministic Bake validation
   - owner/session + Room ownership.
   - Room lifecycle gate.
   - selected ExperienceDNA must exist and pass schema validation.
   - Experience media set must exactly match owner-selected Studio media and contain no duplicates.
   - Theme consistency Room/Studio/ExperienceDNA.
   - Aura + Transition catalog compatibility revalidated.
   - Background music revalidated.
   - Room MP3 must remain Analyze=ready.
   - Selected media B2 objects are HEAD-verified against size metadata.
   - Room-uploaded music B2 object is HEAD-verified.
   - Experience Wish IDs must still reference approved public wishes.
   - Bake never calls Gemini.

3. Versioned Receiver Manifest
   - Replaced legacy ReceiverManifest placeholder.
   - schemaVersion + receiverId + revision + bakedAt.
   - public Room/recipient metadata.
   - selected ExperienceDNA only.
   - normalized media descriptors.
   - safe wishes.
   - Theme palette/typography + ornament placement.
   - background music + beatmap reference/inline analysis.
   - stable asset descriptors.
   - no owner UID/email, moderation state, prompts, credentials, B2 object key, or presigned URL in the public manifest.

4. Stable Receiver asset routing
   - New server-side ReceiverRepository / FirestoreReceiverRepository.
   - Public snapshot: receivers/{receiverId}.
   - Server-only routing records: receivers/{receiverId}/assets/{assetId}.
   - GET /api/receiver/{receiverId}/assets/{assetId} validates asset membership in the CURRENT manifest before resolving.
   - Private asset -> short-lived B2 signed GET redirect.
   - Curated public asset -> same-origin public path redirect.
   - No endpoint accepts arbitrary B2 object key from the client.

5. Atomic publish + stable token
   - Firestore transaction publishes Receiver snapshot, Receiver asset routing records, and Room ready state together.
   - First Bake creates receiverId and revision 1.
   - Re-Bake keeps receiverId and increments revision.
   - firstBakedAt is preserved; lastBakedAt updates.
   - stale asset routing records may remain physically until lifecycle cleanup, but resolver rejects anything not referenced by the current manifest.

6. Re-edit / re-Bake workflow
   - Ready Room can be reopened into configuring.
   - Existing published Receiver remains live while owner edits draft Studio state.
   - Finish page exposes Atur lagi.
   - Next successful Bake atomically replaces the live snapshot under the same token.
